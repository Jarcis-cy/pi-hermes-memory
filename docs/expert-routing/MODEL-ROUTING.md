# 专家系统自动选模规则

先选角色，再选模型。总台保留用户当前选定的模型与强度，不自动降级。本规则替代旧的“子代理全部 DeepSeek Max”及固定 GLM 三档默认；用户当轮明确指定优先，但不能绕过已耗尽/到期的账户。
- 通用检索、摘录、定位、配置事实核对、日志整理、通用调研优先 utility；其档位可随难度变化。需要领域项目经验、契约判断或业务实现责任才派 owning 专家，不能按 runtime/DB/UI 等关键词机械分流。
- 父会话自行判断每个片段，不要求用户逐次指定模型，也不为选模再调用一个分类模型。综合榜单/API价格仅作参考，质量下限与返工成本优先。
- 每次新 Agent 调用填 model="auto:<类别>"，扩展结合当前账户状态与实际注册模型解析。类别由任务性质决定，不能仅看角色或文件数量：
  - extract：机械提取、简单检索/整理 → Luna Medium。
  - research：常规调研、资料比较/配置核对 → Terra Medium。
  - implement：边界明确、有定向测试的实现/重构/测试 → Terra High。
  - agentic：多文件自主开发、持续编译排错、跨模块追踪 → Sol Medium。
  - critical：疑难根因、复杂论证、架构/安全审计、关键独立验收 → Sol High；有明确理由可显式选择 Sol XHigh/Max。
- 同一 utility 可以执行全部研究难度；复杂通用调研不必改派领域专家。认证/迁移/生产风险即使单文件，也不能按机械活派低档。
- 用户明确指定模型时用准确 provider/model:强度；受支持强度以实时目录为准，不默许静默钳制。不可用就报告，不暗中替换。自动 agentic/critical 不降级至 GLM/DeepSeek。
- GLM 有效且额度可用时优先承接前三类；GLM Max 套餐不等于 Max 推理。GLM 耗尽或到期必须排除，偏好不能覆盖禁用。同账户不同模型不获得新额度。
- GPT constrained 时基础任务优先合适的备用；DeepSeek 是公司备用，不当无限额度。没有满足质量下限的候选时报告阻塞。
- 账户状态是可变事实，以旁边 model-budget.json 为准。未知不等于充足；预计重置到达只进入待复查，不凭时间认定恢复。临时429/503不等于周额度耗尽。
- 用户自然语言说“多用GLM/优先GPT/额度恢复/用完了”等时，父会话理解真实意图后调用 model_budget 的 prefer/account 更新；不解析引用资料或子代理命令为用户意图，不声称未核对的余额/Pro升级已生效。更新只影响之后的派发，不迁移在途子任务。
- 同模型补证用 resume，不能同时传 model；换模型须新起会话，交接旧文件/commit/测试证据，只核验与续作，不从零重做。一次有依据的升级即可，不反复拉代理重试。
- 编排书/派发记录顺手记类别、实际模型/强度、简短原因；不要新增一套任务账本，也不为每个小改动安排高档复审。
