# 专家系统自动选模规则

先选角色，再按这次事项选模型。总台保留用户当前模型与强度，不自动降级。本规则替代旧的统一 DeepSeek/固定 GLM/按专家角色默认 Sol；用户明确指定仍须满足账户禁用和 GPT 代际下限。
- 通用检索、摘录、定位、配置核对、日志整理、通用调研优先 utility；需要项目领域经验、契约判断或业务实现责任才派 owning 专家，不能按 runtime/DB/UI 关键词机械分流。
- 不要求用户逐次指定模型，不为分类再调用模型。新建 Agent 必须明确填 model="auto:<类别>"；漏填或只填 auto 会阻断，不按专家身份猜档、不继承父模型：
  - extract：机械提取、简单检索/整理、已有材料的简单对比与粗结论、已知ID的状态摘录 → GPT-6 Luna Max。
  - research：确需补资料的常规调研及配置事实核对 → GPT-6.1 Terra Medium；不是所有对比都归 research。
  - implement：边界明确、有定向测试的实现/重构/测试 → GPT-6.1 Terra High。
  - agentic：多文件自主开发、持续编译排错、跨模块追踪 → GPT-6.1 Sol Medium。
  - critical：疑难根因、复杂论证、架构/安全审计、关键独立验收 → GPT-6.1 Sol High；有明确理由才显式 XHigh/Max。普通对比、表格汇总、报告成文不属此类，不因资料多或主题涉及安全/费用就升档。
- GPT 只用6及以上：Luna用6，Terra/Sol用6.1；同价优先新模型，禁止5.6等旧代，包括显式指定和备用回退。当前新代不可用就报告，不能偷偷退旧代。
- 自动派发用类别；用户明确指定/有理由的升级才用完整 provider/model:强度，派发说明写原因。受支持强度以实时目录为准，不静默钳制。auto解析失败是装载/配置故障，不是自动升级理由，先报告具体错误，不能习惯性改派Sol。
- Luna 6 无论自动还是显式选择都用 max；显式低档直接拒绝并提示 max，不静默改写。实时目录不支持 max 时按能力校验报告不可用，不退到 Luna 低档。最高思考强度不等于扩大报告深度。
- 渐进交付：按用户原问题和要求深度，先复用现有材料，简明并列表/结论并标明缺口；不自加全历史取证、全生命周期核账或重新根因审查，更不以自扩范围论证 critical。用户追问才扩大深度，具体难点才升级，不机械地每次追问升档；真实安全、权限和破坏操作门槛不降低。
- 同一utility可承担全部研究难度；认证/迁移/生产风险即使单文件也不能当机械活。复杂连续修复的局部补证可保留原上下文，不强制为省档从零重做。
- 每次resume前先判断是否仍是同一个复杂问题的连续工作。只有同任务补证/修复才续用，description必须以"[continue] "开头作明确声明，且不能传model；没有声明会阻断。这个声明是父台责任确认，不是系统自动理解了任务语义。
- 独立的工单注释/回读、文档摘录、进度计数、模型ID查找、状态总结，不因同一owner之前用Sol就resume它；按extract/research另派utility，给精确文件/ID和已有证据。相关机械尾活一次合批；不得越过业务owner写域或必要审查/安装权限边界。
- 换模型新起会话，只交接既有文件/commit/测试证据并续作，不重做已交付工作；一次有依据的升级即可，不反复拉代理试错。在途子任务不迁移、不重启。
- GLM有效且额度可用时优先前三类；GLM耗尽/到期必须排除。Max套餐不等于Max推理，同账户不同模型不获得新额度。自动agentic/critical保持GPT质量下限。
- GPT constrained时基础任务优先合适备用；DeepSeek是公司备用，不当无限额度。无满足下限候选就报告阻塞。
- 账户状态以旁边model-budget.json为准；未知不等于充足，预计重置到达只待复查，临时429/503不等于周额度耗尽。
- 用户自然语言要求偏好/账户更新时，父台理解后用model_budget的prefer/account操作；不解析引文为配置指令，不虚构余额或Pro升级，更新只影响后续派发。
- 验证生效看真实父会话路由注入与model_budget status的routing=v3; Luna=max，以及auto实际派出的子模型；不能仅凭磁盘安装或离线stub说已生效。只在父台及其子任务均安全空闲时重载资源，不重启共享pi-web。
- 派发记录顺手记类别、实际模型/强度、理由和是否续用；不要新增任务账本，不给每个小改动安排强档复审。
